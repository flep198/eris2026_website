1. Setting the flux of the primary flux scale calibrator (step 11)

← back to top

The first step is to set the flux density of the flux scale calibrators (in this case, 3C286 and 3C84). This is important because the correlator outputs the visibilities with an arbitrary scaling, so they are not in physical units, i.e., Janskys. However, the visibility amplitudes are correct relative to each other. This means that we can observe a standard source with a physically known flux density (similar to the zero points of a temperature scale), which can then be used to rescale the visibilities and put all fields onto this scale.

In this observation, we found that 1331+3030 (= 3C286) is an almost non-variable radio galaxy, and its total flux density is very well known as a function of time and frequency (Perley & Butler 2013). However, this flux density standard was derived from VLA observations, and the source is somewhat resolved by e-MERLIN.

To mitigate this, we use a model derived from a ~12 hr observation centred on 5.5 GHz. This is scaled to the current observing frequency range (around 5 GHz) using setjy, which derives the appropriate total flux density, spectral index and curvature from parameters in Perley & Butler (2013).

However, a few per cent of the flux is resolved out by e-MERLIN; the simplest way (at present) to account for this is to scale the fluxes derived for the other calibration sources by 0.938 (based on calculations for e-MERLIN by Fenech et al.).

The model consists of delta functions, and setjy enters them into the Measurement Set so that their Fourier Transform can be used as a $uv$-plane model for later comparison with the actual visibility amplitudes. If you make a mistake (e.g. setting a model for the wrong source), use the task delmod to remove it.

  • Take a look at step 11. Enter the correct parameters for the setjy task and for the flux scaling of 3C286. 
    	setjy(vis='**',
		  field='**', reffreq='5.073e9Hz',
		  standard='Perley-Butler 2013', spix=-0.66,
		  model='**', usescratch=True) # You should have downloaded and decompressed this model

2. Bandpass calibration

2A. Investigating decorrelation and solution intervals (step 12)

← back to top

We have set the primary fluxes of the main flux/bandpass calibrators, and we can now move on to calibrating for instrumental and atmospheric effects. If you remember from your introduction to interferometry, we used a model of the locations of our telescopes to correct for the geometric delay and ensure that our signal from the source interferes constructively across all antennae. However, the atmosphere, electronics and engineering of the antennae, and clock and timing errors change the phase and prevent perfect constructive interference. We therefore have to correct for this.

To correct for this, our standard calibration assumes that your calibrator sources are point-like (i.e., flat in amplitude and zero in phase). This means that any deviation must be due to an error. Secondly, there is an assumption that the errors are antenna-independent, i.e., there must be a common factor/error on each baseline to the same antenna. This is sensible, as each antenna will have different clocks (in the case of VLBI), different atmospheric line-of-sights, different LNAs, etc. This also means that we should be able to derive a per-antenna solution and prevents us from simply making our visibilities look like a point source (if we solved per baseline).

We are going to calibrate the bandpass calibrator (0319+4130) first, with the goal of generating a bandpass calibration table. The bandpass is the antenna's response (amplitude and phase) as a function of frequency. This varies rapidly with frequency but is not expected to change with time (at least during the observation), as it is typically due to filters and receiver sensitivities within the antenna. This means we need to obtain solutions for each channel, so we need a very bright source (0319+4130 is 20-30 Jy, so very bright) to provide sufficient signal in each small channel bandwidth. However, before we can derive this correction, we need to first calibrate the other sources of error affecting this source, in order to isolate the bandpass correction.

To begin, we will correct for the phase errors, $\Delta\phi$, which can be parameterised primarily by a constant plus higher-order terms: $$\Delta\phi = \phi_{0}(t,\nu) + \frac{\partial \phi}{\partial \nu}\Delta\nu + \frac{\partial \phi}{\partial t}\Delta t$$ We call $\phi_0(t,\nu)$ the phase error, $\frac{\partial \phi}{\partial \nu}\Delta\nu$, the slope in frequency space, the delay error, and $\frac{\partial \phi}{\partial t}\Delta t$, the slope against time, the rate error. The rate error and higher-order terms are typically needed only for long baselines or low frequencies, where more turbulent atmospheric conditions and separate clocks cause errors. Most modern interferometers, including e-MERLIN, often need to consider only the delay and phase terms.

QUESTION 1: What is the apparent delay error that this corresponds to? What will be the effect on the amplitudes?

Click for answerA change of $2\pi$ radians in $x$ Hz results from a delay error of $1/x$ sec. So a change of 360 deg in 512 MHz is produced by a delay error of $1/(512\times 10^{6})\,\mathrm{sec} \sim 2\,\mathrm{ns}$. If data are vector-averaged across a phase slope, the amplitudes will be reduced, with the reduction increasing with the phase change over the averaging interval. If the combined phase change on a baseline is worse in one polarisation than the other, that polarisation will have a lower averaged apparent amplitude.

QUESTION 2: Delay corrections are calculated relative to a reference antenna, which is assumed to have zero phase, so the corrections factorised per other antenna include any correction due to the reference antenna. Roughly, what do you expect the magnitude of the Cambridge telescope corrections to be? Do you expect the two polarisation hands to have the same sign?

Click for answer The slopes on Mk2 correspond to about 1 turn in 512 MHz, in the same sense for both LL and RR. The slopes on Cm correspond to less than half a turn in the same sense for one polarisation, and about a full turn in the opposite sense for the other. Thus, the combination of errors, which will be solved entirely by correcting Cm, corresponds to magnitudes of $\lesssim 1\,\mathrm{ns}$ and $\sim 4\,\mathrm{ns}$ for the two polarisations, with opposite signs. The slopes, and hence the actual values, vary between spw; see the delay correction plot.

Finally, in preparation for the calibration of the bandpass source, we want to derive the time-dependent phase solution interval. A solution interval is simply the amount of time you average together to derive a correction. Selecting a solution interval can be tricky, but it is all about timescales. On an integration-to-integration basis (a few seconds), your visibilities will be dominated by thermal noise, while on longer timescales the general trends will be dominated by the instrumental/line-of-sight effects that we want to calibrate out. We therefore want to average enough data to track these effects and derive corrections, but not so much that we do not pick up the detailed trends. We shall show this next.

  • Take a look at the final plotms command in Step 12.

		   showgui=gui, overwrite=True)
  • We are plotting the phase versus time for a single scan, single correlation and single channel of the bandpass calibrator. You should see a plot like the one below (coloured by spw)

Some things to note here:

  1. On the 20-30s timescales, we have trackable phase fluctuations caused by the atmosphere, which cause the phases to drift.
  2. These fluctuations are similar across each spw, indicating that the atmosphere affects our frequency range equally (meaning that we could fix the delay and combine spw for higher S/N solutions).
  3. The delays are causing absolute phase offsets between the spectral windows, but crucially, these do not appear to change with time (otherwise the gap between the spectral windows would change with time). Because of this, it is suitable to select a long solution interval (e.g., 600 s in this case) for the delay calibration to maximise the S/N of our solutions.

While we have decided on a solution interval for delays, we need to do the same for the phase term. In the plot below, we have overplotted the phase using different averaging intervals for a single spectral window. You can see that we start to lose the general trends caused by the atmosphere when the averaging is too severe. However, we can also see that there's negligible thermal noise on an integration-to-integration basis, so we could actually use a very short solution interval, such as the 30s shown in the plot. This would track the atmospheric fluctuations well.

3A. Inspect effects of calibration (16)

Important: If you are short on time, skip this step and just read the information and plots shown here.

In this step, we shall apply the delay and bandpass solutions to the calibration sources as a test to verify that they produce a flat bandpass for the phase-reference source (not on the fly this time!). There is no need to apply the time-dependent calibration, as we have not derived it for the phase-reference source yet anyway.

To apply these, we shall use a task called applycal. Some notes on applycal:

  1. The first time applycal is run, it creates a CORRECTED data column in the MS, which is quite slow.
  2. Each time applycal is run, it replaces the entries in the CORRECTED column, i.e. the corrected column is not cumulative, but you can give applycal a cumulative list of gain tables.
  3. applymode can be used to flag data with failed solutions but we do not want that here as this is just a test.
  4. The interp parameter can take two values for each gaintable to be applied, the first determining interpolation in time and the second in frequency. The times of data to be corrected may coincide with, or be bracketed by the times of calibration solutions, in which case linear interpolation can be used, the default, normally used if applying solutions derived from a source to itself, or from phase ref to target in alternating scans. However, if solutions are to be extrapolated in time from one source to another which are not interleaved, then nearest is used. A similar argument covers frequency. There are additional modes not used here (see help(applycal)).
The delay-correction ('K') table contains entries for all sources except the target, so we can use linear interpolation for this one. The bandpass table has only one entry, so we cannot interpolate. Hence, we'd want to select the nearest solutions.

  • Fill in the applycal step in step 16, then look at the following plotms command, which will plot the 'before and after' phase reference phase and amplitude against frequency.

			 field='1302+5748,0319+4130,1331+3030',
			 calwt=False,
			 applymode='calonly',
			 gaintable=['**','**'],
			 interp=['**','**,**'])

5. Determining true flux densities of other calibration sources (steps 18-19)

← back to top

The solutions for 1331+3030 in calsources.a1 include the correct scaling factor to convert the raw correlator units to Jy and remove time-dependent errors. This is used to calculate the scaling factor for the other calibration sources in the CASA task fluxscale. We run this task differently because the calculated fluxes are returned as a Python dictionary. They are also written to a text file. Only the best data are used to derive the flux densities, but the output is valid for all antennas. This method assumes that all sources without starting models are point sources, so it cannot be used for an extended target.

6. Apply solutions to target (steps 20-21)

← back to top

  • Look at and execute step 20 while reading the following information about this step.

This step applies the bandpass correction to all sources. For the other gaintables, for each calibrator (field), the solutions for the same source (gainfield) are applied. gainfield='' for the bandpass table means applying solutions from all fields in that gaintable. applymode='calflag' flags data with failed solutions, which is ok, as we know these were due to bad data. We use a loop over all calibration sources. 

	cals=bases
	cals.remove(target)
	for c in cals:
		applycal(vis='all_avg.ms',
				 field=c,
				 gainfield=[c, '',c,c],
				 calwt=False,
				 applymode='calflag',
				 gaintable=['all_avg.K','bpcal.B1','calsources.p1','calsources.a2'],
				 interp=['linear','nearest','linear','linear'],
				 flagbackup=False)

We then apply the phase-ref solutions to the target. We assume that the phase-reference scans bracket the target scans, so linear interpolation is used except for bandpass. 

	applycal(vis='all_avg.ms',
			 field='1252+5634',
			 gainfield=['1302+5748','','1302+5748','1302+5748'],
